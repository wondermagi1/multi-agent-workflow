# 多智能体软件工程工作台设计

工作台把三次作业的产出连起来。作业一规定怎样发散、质疑、比较和确认需求。作业二用共享黑板、节点与门禁表达流程。作业三在同一数据上呈现角色、运行记录、异常、人工决定和历史时点。用户选择任意节点就能定位它需要的输入、实际产生的产物与导致下一步的原因。

## 主线与人工节点

| 阶段 | 主要交付 | 关键控制 |
| --- | --- | --- |
| S0 想法提出 | 简报、拆解任务、角色及依赖 | 人工定题、冻结输入 |
| S1 多体讨论 | 独立提案、观点、质询、立场与异议 | 四路统一公开、分歧分流、收敛门禁 |
| S2 建设方案 | 有来源的方案 | 关联候选方向和讨论结论 |
| S3 多方评价 | 产品、用户验收与技术三席评分及各自依据 | 同一版本独立评审，硬约束有一席报出违反即阻塞 |
| S4 需求规格 | 需求条目及验收条件 | 记录适用范围、依赖以及未决项 |
| S5 需求确认 | 已确认版本、范围与理由 | 人工显式签收，过期命令拒绝 |
| 实现与交付 | 模拟代码变更、测试和评审产物 | 将结果与对应需求版本关联 |

群体讨论保留同一份冻结输入。初稿互相隔离，必需提案提交齐备后统一写入可见范围。聚类保留原提案出处，质询时按事实、价值和权衡分别处理异议。仍有阻塞问题时可定位到具体意见与证据，显式同意和门禁结论分别记录。

## 从界面追到记录

用户可以按运行、节点和事件序号定位一次活动，从事件找到所用版本、行为、结果、原因与后续状态。失败和重试留在同一时间线上，有序事件支持按历史时点重建状态。历史查看只读，执行命令绑定运行版本并可带命令编号去重。持久化使重启后能够继续查看已有运行。

## HTTP 入口

| 路径 | 用途 |
| --- | --- |
| `GET /api/info` | 当前模型模式与档位 |
| `GET /api/runs` | 本地运行列表 |
| `POST /api/runs` | 使用 `title` 和 `idea` 建立运行 |
| `GET /api/runs/{id}` | 当前状态、可用操作、产物及事件 |
| `POST /api/runs/{id}/actions` | 使用 `action`、`expected_version` 和可选的 `note`、`objection_id`、`command_id` 执行操作 |
| `GET /api/runs/{id}/events?after=0` | 拉取某序号之后的活动 |
| `GET /api/runs/{id}/history?seq=1` | 读取指定事件时点的状态 |
| `GET /api/runs/{id}/workflow` | 导出编排任务、依赖、角色、难度和档位，可用 `seq` 指定历史版本 |

## 六个工作包

分工沿用组内报告的六个工作包。下列分支名和任务编号供后续开发时关联 Issue 与 PR。

| 成员 | 建议分支 | GitHub 任务 | 原型入口 |
| --- | --- | --- | --- |
| 成员 1 | `feat/gate-rules` | **RULE-01** 明确门禁版本、条件与退回位置。**RULE-02** 定义定题、价值裁决、签收的表单和校验。**RULE-03** 规定三类异议分流及恢复条件。**RULE-04** 记录签收范围、依据与变更。 | `workflow/engine.py` 的门禁和人工确认 |
| 成员 2 | `feat/workbench` | **UI-01** 绘制任务依赖、阶段和节点详情。**UI-02** 呈现四席提案、观点来源、质询与分歧。**UI-03** 实现操作控件、待办和状态同步。**UI-04** 展示回放及交付，维护桌面与手机效果图。 | `frontend/` |
| 成员 3 | `feat/blackboard-events` | **DATA-01** 维护黑板对象及引用关系。**DATA-02** 统一事件序号、时点、用量和前后状态。**DATA-03** 管理快照、增量读取和幂等。**DATA-04** 登记工作流、需求及产物版本。 | `workflow/store.py` |
| 成员 4 | `feat/orchestrator` | **ORCH-01** 建立状态转换和任务派发。**ORCH-02** 实现提案并行、汇合及收敛。**ORCH-03** 处理暂停、恢复、重试及旧版本请求。**ORCH-04** 接入模型路由、多方评分与用量统计。 | `workflow/engine.py` 与 `workflow/provider.py` |
| 成员 5 | `feat/evidence-replay` | **TRACE-01** 连接提案、观点、异议和决定。**TRACE-02** 实现按事件回到历史版本。**TRACE-03** 关联需求确认和交付产物。**TRACE-04** 带运行编号记录阻塞、裁决与恢复轨迹。 | `app.py` 的回放接口和 `frontend/` 的运行记录 |
| 成员 6 | `test/disagreement-gates` | **TEST-01** 验证独立稿件公开、共识阈值和阻塞。**TEST-02** 验证人工操作、过期版本和命令去重。**TEST-03** 验证调用失败、重试及用量。**TEST-04** 验证需求签收后才允许进入模拟交付。 | `tests/` |
